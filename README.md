# investor-pitch · 投资人推流 + 查证建档 Skill

一个给 FA（财务顾问）用的 WorkBuddy Skill，覆盖两个场景：

1. **推流**：有项目要融资，从库里筛投资人、写微信开场话术，出「一人一卡」执行文档。
2. **查证建档**：手上有一份驳杂名单（混着投资人、企业老板、FA 同行、律所、媒体、政府招商、私人朋友），全网查证后整理成标准化档案，出 Excel 详情表 + HTML 图表汇报页。

> 本文是给「拿到这个 Skill 的人」看的开箱说明。方法论细节在 `SKILL.md` 和 `references/` 里，跑的时候不用你操心。

---

## 一、三分钟装好

### 方式 A：放进 skills 目录（推荐）

把整个 `investor-pitch` 文件夹放到：

```
~/.workbuddy/skills/investor-pitch/
```

放好后重启 WorkBuddy（或新开一个会话），Skill 就会自动被识别。

### 方式 B：用安装命令

如果你的 WorkBuddy 支持 skill 安装，也可以说：

> 帮我安装 investor-pitch 这个 skill

然后把本目录打包发它，或直接给 GitHub 地址。

**注意**：装的是**整个文件夹**，不是单个文件。`SKILL.md` + `references/` + `scripts/` 要一起，缺了任何一个都会缺功能。

## 二、装完怎么跑（直接说这句话）

### 场景 1：我要推一个项目

> 我要推 **<项目名>**，帮我出推流执行清单

它会问你要三样：项目是什么（或资料路径）、这轮要什么（钱/场景/引荐）、现在到哪一步（轮次金额）。然后跑两道数据闸门 → 筛人 → 写话术 → 出一份按人排列的文档。

### 场景 2：我有一份陌生名单要整理（查证建档）

> 我有一份名单，帮我整理出里面的有效机构和投资人，出 Excel 和 HTML 汇报

然后把清单文件（Excel / CSV / 文本）发它。它会：

1. 先给你**清洗统计**（多少行、多少唯一机构、多少唯一人、多少杂项）——**停下来等你确认**；
2. 你确认口径后，全网查证（机构还活着吗、人还在职吗）；
3. 落成四张标准表；
4. 最后生成 **Excel 详情表 + HTML 图表汇报页**。

**第一次用强烈建议**：先拿 **10 行小清单试跑**，确认你这个环境的联网查证能力 OK，再上真清单。1000 行清单如果拆出几百家机构，是按批排期的活，别指望一次跑完。

## 三、你会拿到什么

### 场景 2（查证建档）的产出

| 产出 | 给谁 | 是什么 |
|---|---|---|
| 四张 CSV（机构主表 / 投资人主表 / 案例证据表 / 待复核表） | 机器 / 数据库 | 标准化落档，字段和枚举受控，能多人合并 |

### 场景 1（推流）的产出

一份「一人一卡」的 Markdown 文档：上面是这个人是谁、为什么推他，下面是两段式微信话术，末尾带空白的发送记录表。

## 四、先分清三条链路（别串）

这个 Skill 里有三条独立的业务链路，触发词不同，别拿错流程去套：

| 链路 | 关卡 | 起点 | 干什么 |
|---|---|---|---|
| **A 推流** | 关卡 0–7 | 本机库里已有的人 | 筛谁 + 写什么话 |
| **B 补档** | 关卡 8 | 本机库里有 1208 人但缺情报 | 把薄页喂厚 |
| **C 查证建档** | 关卡 9 | 手上有一份陌生清单 | 从零查证、分类建档 |

**链路 A/B 依赖本机的投资人数据库**（`~/Library/Application Support/MarxAssistant/marx.sqlite`），你没装 MarxAssistant 就没有这个库，这两条跑不了——这是正常的。

**链路 C 不依赖任何本地库**，只要你的 WorkBuddy 能联网查，就能跑。

---

## 五、环境要求（就一条，但很关键）

**查证建档（链路 C）的效果，取决于你的 WorkBuddy 能不能联网检索。**

- 装了能联网的模型 → 能查到案例级、核实到在岗，产出完整；
- 只能读文件、不能联网 → 只能做到"拆解 + 分类打标"，查证那步会空转，产出大量「待核实」。

不确定的话，先拿 10 行小清单试跑一次就知道了。

## 七、常见问题

**Q：我把名单发它，它直接开始查吗？**
A：不会。它会先出「清洗统计」停下来等你确认口径，确认了才全量查。这是防白跑的设计——聚类口径错了，后面几十批全错。

**Q：查到一半断了怎么办？**
A：它是「每 20 个对象一批、边做边写」的，断在哪儿，结果文件里已经写到哪儿，不会全丢。重跑时跳过已完成的批次即可。

**Q：同一个机构有母子关系（集团 / 子基金）会合并吗？**
A：不会。母子机构各建独立卡，只把"同一法人/同一备案主体"的合并。这是刻意的——合并了母子关系，整组人就查不出来了。

**Q：我和同事各自盘的结果，能合并成一张库吗？**
A：能。只要都按 `archive-format.md` 的四表格式落档，字段名和枚举值一致，就能机械合并。所以**枚举值是受控词表，别自创**——有人写"民营PE"、有人写"国资VC"，就合不上了。
