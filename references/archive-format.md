# 投资人/机构 标准落档格式（v1 · 2026-11-06）

> 用途：全网查证后，把「投资人」和「机构」两套结果落成统一、可机读、可合并的档案。
> 配合《全网查证提示词 v2》使用：提示词管「怎么查」，本文件管「查到之后怎么落」。
> 适用范围：全公司通用。任何人的落档都要落到这四张表的结构上，字段名、枚举值不许改。

---

## 一、总原则（三条，先读）

1. **四表固定，枚举受控**。任何一次查证，输出都是这四张表：机构主表、投资人主表、案例证据表、待复核表。字段名和枚举值以本文件为准，任何人不得自创。
2. **一事实一来源**。每个事实带 `来源URL` + `检索日期` + `可靠性`。没有来源的不写，写「未查到」。
3. **人机构分开，同名列不合并**。人是人、机构是机构，两张表互不覆盖；同名不同人按「姓名+机构」区分。

## 二、四张表的字段字典

### 表 1｜机构主表（orgs.csv）

一行 = 一家唯一机构（按品牌名去重）。**必填字段用 ★ 标。**

| 字段名 | 必填 | 类型 | 说明与示例 |
|---|---|---|---|
| `org_id` | ★ | 文本 | 稳定主键。优先统一社会信用代码；没有就 `ORG-` + 品牌名拼音首字母 + 4位序号（如 `ORG-HSZG-0001`） |
| `org_name` | ★ | 文本 | **品牌名为主键**，人认得的那个（`红杉中国` 而非 `红杉资本股权投资管理(天津)有限公司`） |
| `full_name` | | 文本 | 管理人全称 / 法律主体全称（上例的天津公司） |
| `credit_code` | | 文本 | 统一社会信用代码（18 位），名字会重会改、代码不会 |
| `aliases` | | 文本 | 同一法人/同一备案主体的其他叫法，用 `；` 分隔（`达晨；达晨财智`）。**不许塞母子机构** |
| `entity_type` | ★ | 枚举 | `机构投资人` / `企业方` / `服务商` / `政府招商` / `个人` / `未知` |
| `fund_nature` | ★ | 枚举 | 仅 entity_type=机构投资人 时必填：`国资/政府引导基金` / `市场化VC` / `市场化PE/并购` / `CVC产业资本` / `券商直投/保险AIC` / `家办/个人天使` / `母基金FOF` / `非投资机构` / `未知` |
| `org_type_note` | | 文本 | 母子归属、牌照说明，自由文本（`某集团旗下全资股权投资平台`） |
| `aum` | | 文本 | 管理规模，**必须带口径**：`385亿（截至2025-12，中基协）` |
| `aum_as_of` | | 日期 | 规模口径时间，格式 `YYYY-MM`，缺写空 |
| `reg_no` | | 文本 | 中基协管理人登记编号（`P1020765`） |
| `fund_count` | | 文本 | 在管基金数，带口径（`63只（2026中报）`） |
| `sectors` | | 文本 | 主投赛道，多个用 `；` 分隔 |
| `stage_pref` | | 文本 | 偏好阶段：`天使/种子` / `A轮` / `成长期` / `后期` / `全阶段`，多个用 `；` |
| `ticket_range` | | 文本 | 单笔金额区间，带币种（`2000万-1亿人民币`） |
| `decision_makers` | | 文本 | 决策人姓名，多个用 `；`（指向表2） |
| `contact` | | 文本 | 联系方式（手机/微信/邮箱，注意脱敏：手机中间四位打码） |
| `src_row` | ★ | 文本 | 来源清单行号，可多个用 `；`（回溯用） |
| `org_activity_status` | ★ | 枚举 | `active` / `dormant` / `dead` |
| `last_deal_date` | | 日期 | 最近一笔案例时间 `YYYY-MM`，active 才填 |
| `gate_failed` | | 文本 | 未通过哪道闸（`闸1非买家` / `闸2无案例` / `闸3缺触达` / 空=全过） |
| `verified_at` | ★ | 日期 | 本次核实日期 `YYYY-MM-DD` |
| `notes` | | 文本 | 补充、矛盾点、待核实 |

### 表 2｜投资人主表（people.csv）

一行 = 一个人（按「姓名+当前机构」去重）。同一人历史任职写进 `career`，不另起一行覆盖。

| 字段名 | 必填 | 类型 | 说明与示例 |
|---|---|---|---|
| `person_id` | ★ | 文本 | 稳定主键 `PER-` + 姓名拼音 + 4位序号（`PER-ZHANG-0001`） |
| `name` | ★ | 文本 | 姓名 |
| `aliases` | | 文本 | 英文名/曾用名，`；` 分隔 |
| `current_org` | ★ | 文本 | 当前机构（品牌名，指向表1 `org_name`） |
| `title` | ★ | 文本 | 职位原文（`合伙人`） |
| `decision_role` | ★ | 枚举 | `合伙人` / `MD·董事总经理` / `总监` / `经理` / `分析师` / `未知` |
| `person_status` | ★ | 枚举 | `active` / `warm` / `moved` / `departed` / `unverified` |
| `verified_at` | ★ | 日期 | 在岗核实日期 `YYYY-MM-DD` |
| `career` | | 文本 | 履历分段，旧值不覆盖只追加：`A资本 合伙人(~2024) → B创投 合伙人(2025-)` |
| `focus_sectors` | | 文本 | **个人**专注赛道（比机构更细），`；` 分隔 |
| `stage_pref` | | 文本 | 个人偏好阶段 |
| `ticket_range` | | 文本 | 个人出手区间 |
| `rep_cases` | | 文本 | 本人主导的代表案例（项目名+轮次+时间），无就写「未披露」 |
| `education` | | 文本 | 教育背景（含学校/专业/年份），查不到写空 |
| `base_city` | | 文本 | 常驻城市 |
| `contact` | | 文本 | 联系方式（脱敏） |
| `style` | | 文本 | 投资风格，**须有公开访谈依据**（`决策快；不投早期；要董事席位`） |
| `src_row` | ★ | 文本 | 来源清单行号 |
| `gate_failed` | | 文本 | 未通过哪道闸 |
| `notes` | | 文本 | 补充、矛盾点 |

### 表 3｜案例证据表（deals.csv）

一行 = 一个投资案例（机构、人都可重复出现）。

| 字段名 | 必填 | 类型 | 说明与示例 |
|---|---|---|---|
| `deal_id` | ★ | 文本 | `DEAL-` + 项目拼音 + 轮次 + 序号 |
| `org_name` | ★ | 文本 | 投资方机构（品牌名） |
| `project` | ★ | 文本 | 被投项目名 |
| `round` | ★ | 文本 | 轮次（`天使轮` / `Pre-A` / `A轮` / `B轮` / `战略投资`） |
| `invest_date` | ★ | 日期 | 投资时间 `YYYY-MM` |
| `role` | | 文本 | `领投` / `跟投` / `独家` / `未披露` |
| `amount` | | 文本 | 金额，带币种（`数千万人民币`） |
| `lead_investor` | | 文本 | 主导人姓名，标不出写「未披露」，**不许硬安到名单上的人** |
| `source_url` | ★ | 文本 | 来源 URL |
| `source_type` | ★ | 文本 | `36氪` / `IT桔子` / `中基协` / `工商` / `官网` / `天眼查` / `公众号` 等 |
| `reliability` | ★ | 枚举 | `official` / `registry` / `media` / `aggregator` / `social` |

| `quote` | | 文本 | 原文摘录（关键句） |

### 表 4｜待复核表（review.csv）

一行 = 一个卡住的对象。**不许硬判的都扔这儿，不要停在草稿里。**

| 字段名 | 必填 | 类型 | 说明 |
|---|---|---|---|
| `src_row` | ★ | 文本 | 原始行号 |
| `raw_text` | ★ | 文本 | 原始文本原文 |
| `stuck_at` | ★ | 文本 | 卡在哪一步（`拆三元组` / `机构聚类` / `同名区分` / `在岗核实` / `案例判定`） |
| `tried` | | 文本 | 已尝试的检索词/渠道 |
| `suggestion` | | 文本 | 建议动作（`需人工看名片` / `需问本人` / `等中基协更新`） |

## 三、枚举值总表（受控词表，任何人不得新增）

**entity_type（6）**：`机构投资人` `企业方` `服务商` `政府招商` `个人` `未知`

**fund_nature（9）**：`国资/政府引导基金` `市场化VC` `市场化PE/并购` `CVC产业资本` `券商直投/保险AIC` `家办/个人天使` `母基金FOF` `非投资机构` `未知`

**decision_role（6）**：`合伙人` `MD·董事总经理` `总监` `经理` `分析师` `未知`

**org_activity_status（3）**：`active` `dormant` `dead`

**person_status（5）**：`active` `warm` `moved` `departed` `unverified`

**reliability（5）**：`official` `registry` `media` `aggregator` `social`

**round（受控建议）**：`种子轮` `天使轮` `Pre-A` `A轮` `A+轮` `B轮` `C轮` `D轮及以上` `战略投资` `并购` `其他`

> 任何字段如果出现上述之外的取值，视为**格式违规**，整批打回重做，而不是手工改。

## 四、属性标准（fit_type，推荐类型的核心标签）

> 「属性」回答一个问题：**这个人/这家机构，适合我推什么样的项目？** 它是撮合维度，不是身份、不是赛道。

**两层属性（机构一层 + 投资人一层，都选同一套枚举）**：
同一家机构里，可能有人是财务投资人、有人专做产业并购，所以机构和投资人各带一个 `fit_type`，取值相同。

**`fit_type` 主属性（单选，6 值）**：

| 值 | 含义 | 推项目时的用法 |
|---|---|---|
| `财务投资人` | 看财务回报，不看产业协同 | 通用项目可推，看重估值与退出 |
| `产业投资人/CVC` | 要产业协同、订单、供应链 | 只推跟其主业能勾上的项目 |
| `战略/国资平台` | 要落地、返投、注册地 | 推有落地意愿、愿迁注册地的项目 |
| `政策/引导基金` | 要返投比例、符合当地产业目录 | 推符合当地产业政策的项目 |
| `家办/个人天使` | 要信任、决策快、金额小 | 推早期、金额小、需快决策的项目 |
| `资源型/引荐人` | 不直接投，但能引荐别人 | 不推项目，作关系桥梁维护 |

**三个可加标签（各自独立字段，不塞进一个字段）**：

- `偏好阶段`：`早期` / `成长期` / `后期` / `Pre-IPO` / `全阶段`
- `决策速度`：`快`（能当场拍板）/ `中` / `慢`（要过投委会、流程长）
- `关系深度`：`深`（老朋友/已合作）/ `中` / `浅`（刚认识/陌生）

> 推项目时：先按 `fit_type` 筛掉类型不匹配的，再按 `偏好阶段 + 决策速度 + 关系深度` 排序。

## 五、人看的表（human-facing，目的导向，不锁形式）

> 落档表（四表）给 Agent 和数据库用，字段**强约束**（决定"合"）。
> 人看的表**不锁死列数**，只定目的和底线，形式由用的人现场决定。

### 5.1 目的：四个动作要顺

| 动作 | 要能回答 | 触发场景 |
|---|---|---|
| **筛** | 项目来了，快速捞出"可能对得上"的人 | 有项目要推 |
| **看** | 打开一个人，立刻知道"是谁、能不能推、为什么、怎么联系" | 准备联系前 |
| **跟** | 推没推、回了没回、下一步干嘛 | 日常维护 |
| **合** | 多台电脑/多人盘的结果，能并进一张库不打架 | 团队协作 |

### 5.2 底线（三条，满足即合格，其余自由）

1. **必须能回答四问**：他是谁（身份/机构/职位）· 能不能推（属性/状态/阶段）· 怎么联系（微信/手机/城市）· 上次推到哪（跟进/来源）。列多列少都行，四问答不上就缺。
2. **机构必须是"块"**，投资人嵌在机构块内。人不能散掉，否则主次就丢了。
3. **长文本不进筛选表**。履历、案例、风格、跟进记录这些"读"的东西，放档案页，别堆进筛选表——一塞进去就变成没人愿意拖的大宽表。

### 5.3 最小可用骨架（10 列，够跑，不够再加）

新手别一上来铺 20 列。**先这 10 列跑起来，缺哪加哪**：

`机构名`(块) · `机构属性` · `投资人` · `职位` · `个人属性` · `专注赛道` · `偏好阶段` · `微信` · `常驻城市` · `跟进状态`(可写)

> 四问对照：他是谁 → 机构名/投资人/职位；能不能推 → 属性/赛道/阶段；怎么联系 → 微信/城市；上次推到哪 → 跟进状态。四问齐了，剩下的（手机/邮箱/单笔金额/代表案例/决策速度/关系深度/来源/负责人…）按需加。

### 5.4 单人档案（长文本的家，可自由分块）

筛选表装不下的都进单人档案，一人一份。分块**不锁死**，常见是这几块，缺哪补哪：

- 基本信息（姓名/别名/机构/职位/属性）
- 联系（微信/手机/邮箱/城市）
- 履历（教育 + 历史任职，跳槽旧值不删）
- 投资偏好（赛道/阶段/金额/速度/风格）
- 关系（深度/怎么认识/引荐人/状态）
- 跟进记录（时间 + 动作，**append-only 不覆盖**）
- 证据与来源（中基协/工商/融资新闻署名）

> 单人档案对应四表 `people.csv` 一行 + 该人 `deals.csv` 案例 + `review.csv` 待核，可机械生成、可人工补写——但人工补的要单独标，机器重算不得覆盖（对齐 L2/L3 分层纪律）。

## 六、本地资料库 = 可选数据源（格式兼容，不做本机合并）

任何一台电脑的本地资料（历史库、已查证档案、wiki 页）都可以作为**盘点过程中的一个输入源**，前提是能导出成四表结构。

- **查证前置闸（可选）**：有本地库时，先拿机构名/人名做模糊匹配，命中的继承已有情报（标 `本地已有`），只对差集做全网查；没本地库则直接全网查。
- **不写死合并**：合并是可选动作，不是流程。格式统一了，合不合并是自由的。
- **目的**：维护好那份**指定的数据库/档案**，本地库只是喂料，不是真身。

## 七、分档汇总（summary sheet）

四表之外，额外一个汇总 sheet，列以下统计块：

- **A 档**：机构 `active` + 人在职决策岗 → 可推
- **B 档 / warm**：人在职决策岗，机构无案例可证 → 可推但降级
- **C 档**：在职非决策岗 / 信息不全 → 建档观察
- **moved 名单**：已跳槽的人（含新去向）—— 最易漏、最有价值
- **departed 名单**：已离开投资行业
- **死机构池**：`dead` 与 `dormant` **分列**（dead 永久、dormant 可复活）

每块一行统计数字 + 明细行号引用，方便直接导入后续系统。

## 八、落档纪律（违反 = 格式不合格）

1. 字段名、枚举值**一字不差**照抄本文件。
2. 空值写「空」或「未查到」，**不写「无」「N/A」的自创变体**，也不删列。
3. 规模/阶段/金额类**必带口径与时间**（`as_of` 或括号内注时间）。
4. `lead_investor` 标不出就「未披露」，不许脑补安到名单上的人头上。
5. 联系方式脱敏：手机号中间四位 `*`。
6. 分批落：每 20 个对象一个 batch，追加写，不覆盖。
7. 每次落档跑一次「格式自检」（见下），全过才算交付。

---

## 九、格式自检（交付前必跑）

- [ ] 四张表 + 汇总 sheet 齐全，字段名与本文件一致
- [ ] 枚举值全部命中受控词表，无自创值
- [ ] 每个 `active` 机构有 `last_deal_date`；每个 `dead` 机构有硬证据链接
- [ ] 每个投资人都有 `verified_at`（在岗核实日期）
- [ ] 所有规模/金额带口径与时间
- [ ] moved 名单已单列且含新去向
- [ ] 无空列被删、无枚举外取值
- [ ] 每行可回溯到「来源清单行号」
