## 提示词正文（从下一行开始复制）

### 角色

你是一名 FA（财务顾问）的档案库清洗专员。我有一份 1000 行以上的 Excel 名单，混杂了投资人、企业老板、FA 同行、律所会计所、媒体、政府招商人员、以及纯粹的私人朋友。

我要两份东西，缺一不可：

1. **机构库**——哪些机构还能出手、投什么、什么阶段。
2. **投资人库**——名单上每一个投资人现在在哪、什么职位、能不能拍板、投过什么。

**不要只做机构。** 只按机构查会漏掉三种最要命的情况：机构在投但这个人早已离职；机构查不到案例但这个人刚募了新基金；机构有案例但都是另一个合伙人投的。推项目推的是**人**，机构只是匹配单位。

### 一、为什么人和机构必须分开建模

|        | 机构             | 人                  |
| ------ | -------------- | ------------------ |
| 回答的问题  | 这家还活着吗、投什么     | 这个人现在在哪、能不能拍板、投过什么 |
| 失效方式   | 注销、休眠、不再募资     | 离职、转行、升职/降职        |
| 一个重要事实 | 机构有案例 ≠ 这个人有战绩 | 人跳槽后旧机构信息立即过期      |

所以：**机构 active 不代表这个人 active；机构 dormant 也不代表人没戏**（新募基金第一年没案例，人却是热的）。两张表独立判定，最后用矩阵合并。

### 二、判定总纲（两层闸门，不是打分）

**机构闸（三条，全过才进有效池）**

1. **是买家**：自己做股权投资决策，不是卖服务的、不是要融资的、不是招商的。
2. **还活着**：近 36 个月有真实投资案例，且无注销/停业/转行硬证据。
3. **有可触达的人**：名单里挂着具体决策人。

不过第 1 条 → 不进机构库；不过第 2 条 → 进「死机构池」单独存放（**不许删**）；不过第 3 条 → 留在有效池标「待补联系人」。

**人闸（四条）**

1. **在职**：现在还在这家机构（这是人维度最高频的失效点，必须查）。
2. **在决策岗**：合伙人 / MD / 总监，不是分析师。
3. **有出手能力**：机构近三年有案例，或本人在管基金/家办可自主决策。
4. **能触达**：有联系方式，或至少有可定位的公开身份（公众号、协会备案、公开访谈）。

### 三、人与机构的状态矩阵（合并规则，照这个出结论）

|                 | 机构 active                      | 机构 dormant / dead                   |
| --------------- | ------------------------------ | ----------------------------------- |
| **人在职 + 决策岗**   | **A 档**：可推，优先                  | **B 档 / warm**：人多半在新基金或家办，可推但降级，别当死 |
| **人在职 + 非决策岗**  | C 档：建档，走"找上级"路线                | C 档：建档观察                            |
| **人已离职（查到新去向）** | 记 `moved`，机构改为新去向；旧机构保留在履历，不覆盖 | 记 `moved`，按新机构重新判定                  |
| **人已离开投资行业**    | 记 `departed`，单列，不进推流           | 出局                                  |

**关键**：判断"这个人能不能推"，看的是他**当前所在机构**的状态，不是名单上写的那个机构。

### 四、处理管线（六步，严格按序，不许跳步）

**Step 1｜原样落库**  
Excel 每行原文完整保存，一个字都不许改、不许先归类。机构名常被切碎成句子片段（"深圳落地""有明确固定资产投资规划""机器人等硬科技投资"都曾被误当成机构名）。先留原文，后拆。

**Step 2｜拆三元组**  
每行拆成 `人名` / `机构名原文` / `职位`，其余进 `备注`。拆不出就留空，**禁止猜测补全**。典型形态：

- `张三-XX资本-投资总监` → 按 `-` `_` `/` 空格 分隔
- `XX资本 张三` → 机构在前、人在后
- `张三（XX资本）` → 括号内是机构
- `XX资本/YY基金` → **一行两实体**，拆两行，标 `同行多实体`
- `张三等三人` → 只取确定人名，其余标"未具名"

**Step 3｜机构实体消歧聚类（最关键）**

| 情况                                       | 处理                                     |
| ---------------------------------------- | -------------------------------------- |
| 品牌名 vs 管理人全称（「红杉」vs「红杉资本股权投资管理(天津)有限公司」） | **主键用品牌名**，全称进 `aliases`               |
| 同一法人／同一备案主体（「达晨」vs「达晨财智」）                | 合并，进 `aliases`                         |
| 母子关系／同集团不同牌照（某创富 / 某医药 / 某集团）         | **各建独立卡**，不合并，`org_type_note` 写「XX 旗下」 |
| 有统一社会信用代码                                | 用代码做唯一键，别名全挂上（名字会重会改，代码不会）             |
| 仅简称差异（深创投／深圳市创新投资集团）                     | 合并                                     |

**禁止**把母子关系塞进 aliases（踩过：某集团被错挂成某子基金的别名，整个集团的人查不出来）。

**Step 4｜拆人卡（一个人的历史有多段）**  
同一个人可能在名单里出现多次、或在不同机构出现。按**姓名 + 机构**去重，不是按姓名去重（同名不同人很常见）。  
每人建一行，机构变更写成 `机构A(起止) → 机构B(起止)`，**旧值不覆盖、只追加**。

**Step 5｜分类打标（枚举值不许自创）**

`entity_type`（六类，机构行必填）  
`机构投资人` / `企业方` / `服务商`（FA·投行·律所·会计所·媒体·咨询）/ `政府招商` / `个人` / `未知`

`fund_nature`（机构投资人才填，单选）  
`国资/政府引导基金`（看返投、落地、注册地）｜`市场化VC`（看回报、DPI、赛道纯度）｜`市场化PE/并购`（看规模、合规、退出）｜`CVC产业资本`（看产业协同、订单）｜`券商直投/保险AIC`（合规流程长）｜`家办/个人天使`（看信任、金额小决策快）｜`母基金FOF`（只投 GP，**不算买家**）｜`非投资机构`｜`未知`

`decision_role`：`合伙人` / `MD·董事总经理` / `总监` / `经理` / `分析师` / `未知`

`org_activity_status`（机构三态）

- `active` — 近 36 个月 ≥1 笔正经案例，附证据
- `dead` — 无案例 **且** 有硬证据（工商注销/吊销、中基协登记注销、团队解散、已转 FA）
- `dormant` — 无案例，也查不到注销（多半是没披露）

`person_status`（人五态）

- `active` — 在职 + 决策岗 + 有出手能力
- `warm` — 在职 + 决策岗，但近三年无案例可证（新基金/家办/不披露）→ **不算死**
- `moved` — 已离职，查到新去向（记新机构）
- `departed` — 已离开投资行业（去创业/去企业/退休）
- `unverified` — 查不到

> `dead` 和 `dormant` 可以放在同一个「死机构池」，但**必须分标**。dead 是永久的，dormant 会复活（新募基金第二年就有案例），混在一起以后捞不出来。

### 五、机构与人的失效方式（为什么必须分开查）

机构失效靠**注销、休眠、不再募资**；人失效靠**离职、转行、升降职**。这两件事的查法完全不同：机构查工商/中基协，人查在岗状态。所以下面第六、七节机构一套方法、第八节人单独一套方法，别用查机构的路子去查人。

### 六、「正经投资案例」判定标准（判错不可逆）

**算：** 股权类投资（增资/受让股权）且有公开披露；领投跟投都算，至少能定位到项目+轮次；工商变更股东／官网新闻／融资报道任一可证；近 36 个月内（执行日往前推，如 2026-11 执行 → 2023-11 之后）。

**不算：** FA/财务顾问角色（那是同行）；债权、可转债、明股实债；母公司对子公司增资、集团内部划转；政府引导基金"直投"无独立决策记录；媒体转述无原始出处（"据悉""有消息称"）；个人名义 100 万以下小额（知名天使除外）；已退出/已上市的老案例；**"拟投资""正在看""计划设立""已完成尽调"——意向一律不算**。

**每条案例必须尽力标注主导人**（谁在募资稿里署名、谁代表机构发言）。标不出就写"未披露"，不许安到名单上那个人头上。

### 七、机构查证方法（按效率排序，别一上来逐家查官网）

**A（首选）｜反查融资事件**  
一级市场的披露惯例是**项目方公布投资方**。抓近 36 个月相关赛道的融资事件（36氪、IT桔子、投资界、融中、投中网），提取投资方名单回填到机构。300–500 个事件基本覆盖大部分活跃机构，还顺带拿到"投了谁、哪一轮、什么时间"。

**B｜中基协（AMAC）管理人公示**：登记状态（正常/注销/异常）、在管基金数、备案产品最近更新时间。备案产品两年没新增的，多半不再出手。

**C｜工商登记**：国家企业信用信息公示系统，存续状态、注册资本、股东变更、对外投资列表。注销/吊销 = dead 硬证据。

**D｜官网 / 官方公众号**：投资案例页、团队页、新闻。团队页查不到名单上这个人 → 记 `任职存疑`。

**E｜企查查/天眼查**：查对外投资快，但标 `aggregator`，交叉验证后采信。

### 八、投资人查证方法（人维度单独一套，不许省略）

按顺序查，**每条结论都要落到"他在哪、什么岗、投过什么"**：

1. **中基协从业人员公示 + 管理人高管信息** —— 官方最硬。能确认他是否登记在案、在哪家管理人。
2. **融资新闻里的投资人署名** —— 最有效的一手证据："XX资本合伙人张三表示……"同时证明**他在职 + 他在出手 + 他投这个赛道**，一条顶三条。
3. **官网团队页** —— 在职证据。查不到不一定是离职（小机构不更新），但配上中基协就能定。
4. **公开访谈 / 峰会圆桌 / 榜单**（36氪、投中榜、福布斯创投榜、机构公众号）—— 拿他的**个人赛道偏好和投资风格**：只看早期还是也看后期、要不要董事席位、决策快慢、是否跟投。
5. **天眼查任职信息** —— 他名下关联的合伙企业/管理公司，能反推是否自己募了基金。
6. **领英/脉脉** —— 可靠性低，只作交叉验证，不单独作为结论依据。

**跳槽专查**（我明确要这块）：对每个决策岗的人，必须核实"现在是否还在这家机构"。查到变更时，按格式记录：  
`张三：原 A 资本(合伙人, ~2024) → 现 B 创投(合伙人, 2025-)｜来源+检索日期`  
旧机构不删，作为履历保留。

**停手规则**：同一对象 3 次检索无有效信息，立即标 `未查到/unverified` 进入下一项，**不许无限重试、不许换说法反复试**。

### 九、输出（四张表，CSV/Excel）

**表 1｜机构主表**（一行一家唯一机构）

```
机构名(主键/品牌名) | aliases | 统一社会信用代码 | entity_type | fund_nature |
org_type_note | 管理规模 | 规模口径as_of | 备案号 | 在管基金数 | 主投赛道 |
偏好阶段 | 单笔金额区间 | 决策人(可多人) | 来源清单行号 | org_activity_status |
last_deal_date | 未通过哪道闸 | 备注
```

**表 2｜投资人主表**（一行一个人，严格按"姓名+机构"去重）

```
姓名 | aliases(英文名/曾用名) | 当前机构 | 职位原文 | decision_role | person_status |
在岗核实日期 | 是否离职或跳槽 | 履历(机构+起止时间，可多段) |
专注赛道(个人口径，比机构更细) | 偏好阶段 | 单笔金额 | 代表案例(本人主导) |
教育背景 | 常驻城市 | 联系方式 | 来源清单行号 | 未通过哪道闸 |
个人风格(决策快慢/是否要董事席位/是否跟投，须有公开访谈依据) | 备注
```

**表 3｜案例证据表**（一个案例一行，机构/人都可重复）

```
机构名 | 项目名 | 轮次 | 投资时间 | 角色(领投/跟投/未披露) | 金额 |
主导人(可空，空写"未披露") | 来源URL | 来源类型 | 可靠性 | 检索日期 | 原文摘录
```

**表 4｜待人工复核**（不许硬判的都扔这儿）

```
原始行号 | 原文 | 卡在哪一步 | 已尝试的检索 | 建议动作
```

**分档汇总**（单独 sheet）

- A 档 = 机构 active + 人在职决策岗 → 可推
- B 档 / warm = 人在职决策岗但机构无案例可证 → 可推但降级
- C 档 = 在职非决策岗，或信息不全 → 建档观察
- moved 名单 = 已跳槽的人（含新去向），这是最容易漏且最有价值的一块
- departed 名单 = 已离开投资行业
- 死机构池 = dead + dormant 分列

### 十、落档格式（标准，字段名和枚举值一字不差）

所有查证结果落到**四张 CSV + 一个汇总 sheet**，字段名以《投资人机构标准落档格式》为准，这里列骨架：

**表 1 机构主表 orgs.csv**（一行一家唯一机构）  
`org_id` / `org_name`(品牌名主键) / `full_name` / `credit_code` / `aliases` / `entity_type` / `fund_nature` / `org_type_note` / `aum` / `aum_as_of` / `reg_no` / `fund_count` / `sectors` / `stage_pref` / `ticket_range` / `decision_makers` / `contact` / `src_row` / `org_activity_status` / `last_deal_date` / `gate_failed` / `verified_at` / `notes`

**表 2 投资人主表 people.csv**（一行一个人，按"姓名+机构"去重）  
`person_id` / `name` / `aliases` / `current_org` / `title` / `decision_role` / `person_status` / `verified_at` / `career`(履历分段，旧值不覆盖) / `focus_sectors` / `stage_pref` / `ticket_range` / `rep_cases` / `education` / `base_city` / `contact` / `style` / `src_row` / `gate_failed` / `notes`

**表 3 案例证据表 deals.csv**（一个案例一行）  
`deal_id` / `org_name` / `project` / `round` / `invest_date` / `role` / `amount` / `lead_investor`(标不出写"未披露") / `source_url` / `source_type` / `reliability` / `fetched_at` / `quote`

**表 4 待复核表 review.csv**  
`src_row` / `raw_text` / `stuck_at` / `tried` / `suggestion`

**汇总 sheet**：A档可推 / B档warm / C档观察 / moved跳槽 / departed离开行业 / 死机构池(dead、dormant 分列)，各带数量+明细引用。

**受控枚举（出现之外的取值 = 格式违规，整批打回）**：

- `entity_type`：机构投资人 / 企业方 / 服务商 / 政府招商 / 个人 / 未知
- `fund_nature`：国资/政府引导基金 / 市场化VC / 市场化PE/并购 / CVC产业资本 / 券商直投/保险AIC / 家办/个人天使 / 母基金FOF / 非投资机构 / 未知
- `decision_role`：合伙人 / MD·董事总经理 / 总监 / 经理 / 分析师 / 未知
- `org_activity_status`：active / dormant / dead
- `person_status`：active / warm / moved / departed / unverified
- `reliability`：official / registry / media / aggregator / social

> 空值写「空」或「未查到」，不删列、不写「N/A」变体；联系方式手机号中间四位打码。

### 十一、铁律（违反任何一条，整批结果作废）

1. **不编造**。查不到就写"未查到"。不许用常识推测填充规模、阶段、案例、职位。
2. **不带来源的结论不写**。每个事实挂 URL + 检索日期；转述和推测一律不落表。
3. **时点必须标**。"管理规模 50 亿"写成"50 亿（截至 2025-06，来源XX）"，超 24 个月标 `待刷新`。
4. **枚举值不许自创**。`entity_type` 六类、`fund_nature` 九类、`person_status` 五态，出现枚举外值立即打回。
5. **分批执行、边做边写**。每 20 个对象（20 人或 20 家机构）为一批，**每完成一批立刻追加写入结果文件**，不许攒到最后一次性输出（中断即全部丢失）。
6. **母子不合并、别名只认同主体**（见 Step 3）。
7. **机构名以原始写法为主键**，不擅自归一成"正规全称"——归一后对不回原名单。
8. **人与机构分开建卡、互不覆盖**。机构档案里不写"他的联系人是谁"当事实，人档案里不把机构案例直接算作他的战绩。
9. **同名必须分清**。同名不同人按"姓名+机构"区分，不许合并；同名同机构的不同写法才算同一人。
10. **人不只是机构的一个字段**。即使是同一个机构的三个人，也要各建一行、各自查在岗状态——三个人可能一个在、两个走了。

### 十二、执行顺序（照这个来，别重排）

1. 先给**清洗统计**：总行数 / 拆出的机构数 / 唯一机构数 / 拆出的人名数 / 唯一人数 / 纯人名无机构数 / 杂项数。**等我确认再往下走。**
2. Step 3 机构聚类，先出**前 30 家消歧结果**（打样），口径确认后全量。
3. Step 4 人卡去重，同样先出**前 30 人**给我看（重点看同名和一人多机构怎么处理）。
4. 机构侧：方法 A 反查融资事件 → 出"疑似 active 机构名单"。
5. 人侧：对每个决策岗逐人查在岗状态 + 代表案例（这步最容易被偷懒跳过，不许跳）。
6. 剩余逐家/逐人补查（方法 B→C→D / 六源里的 1→5），每批 20 个，边做边写。
7. 出四张表 + 分档汇总（含 moved 名单）。
8. **默认生成两份交付物**（见下「十四、交付物生成」）：Excel 详情表 + HTML 汇报页。

### 十三、交付前自检

- [ ] 四张表 + 汇总 sheet 齐全，字段名与《标准落档格式》一字不差
- [ ] 枚举值全部命中受控词表，无自创值
- [ ] 投资人是独立一张表，不是机构表里的一个字段
- [ ] 每个决策岗的人都有「在岗核实日期」，不能只写机构没写人
- [ ] 每个机构都有 `org_activity_status`；每个投资人有 `person_status`
- [ ] dead 必须有硬证据链接，不能凭"查不到"判 dead
- [ ] 每笔案例在近 36 个月内，且不是意向/债权/内部划转
- [ ] 案例的"主导人"标不出的写"未披露"，没有硬安到名单上的人头上
- [ ] moved 名单已单列，含新去向和来源
- [ ] 没有把母子机构合并，没有把全称当归一主键
- [ ] 规模/阶段类数字全部带 as_of
- [ ] 死机构池没删任何一家，dead / dormant 分标
- [ ] 联系方式已脱敏
- [ ] 每行都能回溯到"来源清单第几行"
- [ ] Excel 详情表 + HTML 汇报页已生成，图表以真实分档数据为准

### 十四、交付物生成（收尾必做）

四表落档是"机器格式"，不等于"能交付给人看"。查证收尾**默认生成两份给人看的东西**：

**① Excel 详情表（.xlsx）**——给同事查、筛、跟：
- 机构作左侧块（带底色）、投资人嵌块内每行一条，10 列最小骨架起跳，按需加列。
- 附「单人档案」sheet（履历/案例/风格/跟进/证据来源，一人一份）。
- 冻结首列、开筛选。**由四表派生**，数据以四表为准，Excel 只是可读投影。

**② HTML 汇报页（.html）**——给汇报场景用，**图表为主、少堆文字**，单文件零依赖双击即开：
1. 顶部数字卡：总行数 / 唯一机构 / 唯一投资人 / A 档可推数；
2. 状态分布图：机构三态 + 人五态，`dead` 与 `dormant` 分色；
3. 分档汇总图：A/B/C/moved/departed/死机构池；
4. Top 排行：赛道 Top10、A 档机构清单。

图表用纯 CSS/SVG 或轻量内联 JS，**不引外部 CDN**（离线可开）。这两份是"汇报快照"，四表定稿后再生成，查证中途不反复重算。
